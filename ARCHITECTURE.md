## 1. Status in one screen

Zero-dependency, framework-agnostic datepicker in strict TypeScript: an imperative `Datepicker` class plus a `<ten-protons-datepicker>` Web Component (alias `<x-datepicker>`). ESM only.

**Implemented:** single / range / multiple selection (range and multiple are separate modules); popup and inline calendar; one or two months; WAI-ARIA date-picker dialog pattern (roving tabindex grid, live region, focus trap, focus return); full keyboard navigation (RTL aware); manual input parsed on blur/Enter with validation; `Intl`-based localization (names, first weekday, RTL, derived default format); token `dateFormat`; min/max/disabled dates/weekdays; light/dark theming with CSS variables and replaceable class names; Unix timestamp input (always) and output (`outputTimestamp`); month / year grids (always on, in core: the month and year in each header are buttons that open a grid over the days, navigation only; `yearRange` option / `year-range` attribute, §7.9); optional time selector (`enableTime`, separate module: three buttons, each opening a grid of its values over the days, in the same shared grid); UTC backend conversion (`valueInUtc`); `<x-datepicker>` with form association; a demo page; an English README.

**Not implemented:** presets, ms timestamps, CJS build, custom time format, time-of-day min/max, different time per date in range/multiple, any automated tests in the repo (see §9), Ukrainian-only UI strings beyond `locales/uk`.

**Never verified:** behaviour in a real browser through a human (only jsdom + a few headless-Edge screenshots of the generated markup), screen readers, mobile, Safari/Firefox, `npm publish`, whether the name `ten-protons-datepicker` is free on npm.

**Size (measured from the user's own `dist/` at b5396cc, `gzip -9`):** core JS (`index` + shared chunks, concatenated) **≈ 8.9 KB** — _over_ the 7.5 KB target in the original spec; `+range` ≈ +0.15 KB (9.0), `+time` ≈ +0.5 KB; `core.css` 1.4 KB, `themes.css` 0.3 KB; `wc.js` is 3.5 KB on its own (it inlines the CSS) on top of the core chunk. Core grew with timestamps, time parsing and the UTC conversion; trimming it is open work.

## 4. Public API

### Class `Datepicker extends EventTarget`

`new Datepicker(el: HTMLElement, options?)` — `el` is an `<input>` (popup mode) or any element (`inline: true`).
Methods: `open()` (moves focus into the grid), `close()`, `toggle()`, `destroy()`, `getDate()`, `setDate(date, triggerChange = false)`, `setOptions(partial)`, `jumpToDate(date)`, `setRange(start, end)`, getter `strings`. Readonly `el`.
Events (CustomEvent on the instance, plus `on*` callbacks): `change` (detail = `getDate()`), `open`, `close`, `monthChange` (detail = `Date` of the 1st of the new month), `yearChange`. `change` additionally dispatches native bubbling `input` and `change` events on the input (for v-model style bindings). `addEventListener` is typed via interface merging with `DatepickerEventMap`.

## 5. The central idea: picker dates vs values

This is the invariant most likely to be broken by an edit. Read it twice.

- **Picker date** — what the picker stores internally (`sel`, `pending`, `focus`, `view`, `lo`/`hi`): a `Date` in the **browser's local time**. Date-only picker: _local midnight_ of the day the user sees. With `enableTime`: the _local wall-clock_ time to the second (`ms = 0`). All grid logic uses `dayKey(d)` (an integer `y*10000+m*100+d`, local fields) — never timestamps — so DST cannot skew comparisons.
- **Value** — what crosses the public API: `Date`, ISO string or Unix-seconds number going **in** (`selected`, `setDate`, `min/maxDate`, `defaultDate`, `disabledDates[]`, `jumpToDate`, WC `value`, typed ISO/timestamps) and `getDate()`/events/`isoInput`/WC `value` going **out**.

`Day.ts` is the _only_ place the two meet:

| function                              | direction       | behaviour                                                                                                                                                                                                                                                      |
| ------------------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fromInstant(d, time, utc)` (private) | value → picker  | `utc && !time` ⇒ the **UTC calendar day** of the instant (`makeDate(getUTC*)`); otherwise `normDate(d, time)` (local midnight, or keep time minus ms)                                                                                                          |
| `toInstant(d, time, utc)`             | picker → value  | `utc && !time` ⇒ **UTC midnight** of the picker day; otherwise `new Date(d)` (same instant)                                                                                                                                                                    |
| `toUnix(d, time, utc)`                | picker → value  | `floor(toInstant(...)/1000)`                                                                                                                                                                                                                                   |
| `formatISO(d, time, utc)`             | picker → value  | `yyyy-MM-dd`; with `time`: `yyyy-MM-ddTHH:mm:ss` (local, no zone) or with `utc` the UTC instant `…Z`                                                                                                                                                           |
| `parseISO(s, time, utc)`              | value → picker  | ISO date or date-time (`T` or space, optional `.fff`, optional `Z`/`±hh[:]mm`); zone-less date-time = local, or UTC with `utc`; a zone always wins; a **bare date names a calendar day** (no conversion) except a time picker + `utc` reads it as UTC midnight |
| `parseUnix(s, time, utc)`             | value → picker  | `^\d{9,11}$` only (seconds, years 1973–5138)                                                                                                                                                                                                                   |
| `parseValueList(text, time, utc)`     | value → picker  | scans for ISO/timestamp tokens separated by whitespace `, ; /` dashes; `null` if anything else remains                                                                                                                                                         |
| `toDate(v, time, utc)`                | value → picker  | `Date`/string/number → picker date or `null`                                                                                                                                                                                                                   |
| `normDate(d, time)`                   | picker → picker | strip to midnight, or keep time minus ms                                                                                                                                                                                                                       |

Where the conversion is **applied** (all in `Datepicker.ts`): `resolve()` (`lo`, `hi`, `skip`), `home()`, `normalize()` (used by the constructor for `selected`, `setDate`, `setOptions({selected})`), `jumpToDate`, `read()` (typed ISO/timestamps), `getDate()`, `writeISO()`.

Where it must **NOT** be applied (these are bugs I almost shipped, now handled):

1. The picker's _existing_ selection (`this.sel`) is already in picker form. `setOptions` re-normalises it with `normDate`, **not** `normalize()` (which would convert again and shift days east of UTC).
2. A prefilled `<input>` value goes through `read()` (already picker dates) and straight to `mode.clean`, **not** through `normalize()`. The constructor has a comment about this.
3. `parseDates()` (typed _display-format_ text) is local wall-clock — it is what the user sees. Never convert it.
4. `disabledDates` as a function and `disabledDaysOfWeek` operate on displayed days.

Default (`valueInUtc` false, `enableTime` false) behaviour must remain: value == local midnight `Date`.

## 6. Runtime architecture

```
                         ┌───────────── options / WC attributes ─────────────┐
 typed text ─┐           ▼                                                   │
 setDate()  ─┼─► Day.ts (values → picker dates) ─► Datepicker { sel, pending, tod, focus, view, hover }
 selected   ─┘                                              │  state()  (pure snapshot: ViewState)
                                                            ▼
 pointer/keyboard ─► Calendar (delegated listeners) ─handlers─► Datepicker.pick/move/nav/setTime/…
                          ▲ update(ViewState): layout() on month change, else paint()
                          │
 Datepicker ─► getDate()/writeISO()/emit()  ─ picker dates → values (Day.ts) ─► app, isoInput, events
```

- **`Datepicker` owns all state**; `Calendar` is a dumb view: `update(ViewState, focus?)` where `ViewState = { view, focus, keys, span, preview, today, time, disabled(), canPrev, canNext, years, monthOff() }`. `Datepicker.refresh(focus = false)` = `cal?.update(state(), focus)`; it is cheap and called after every change.
- **State fields:** `sel` (committed picker dates), `pending` (unfinished selection, e.g. range start; shown but never emitted; cleared on commit/close), `tod` (time of day given to newly picked days; follows `sel[0]` and the selector; survives Clear), `view` (first day of the first visible month), `focus` (roving-focus day, always clamped to min/max and inside the visible months), `hover` (day key for range preview; set by pointer _and_ keyboard focus moves).
- **`reveal(d, panel?)`** = clamp `d`, set `focus`, shift `view` minimally so `focus` is visible (also never before `monthStart(min)`), emit `monthChange`/`yearChange` through `setView`. With `panel` the month of the (clamped) focus goes into that panel (`view = month - panel`) instead: that is how a month / year grid pick keeps the chosen month in the panel it was chosen from. Callers: pick, move, open, setDate, commitInput, setOptions, `show` (the grid pick, §7.9).
- **`setSel(next, emit)`** is the single commit point: compares (`dayKey` date-only, instant with `enableTime`), assigns, updates `tod` from `next[0]`, clears `pending`, `writeInput()` (text + `isoInput`), `refresh()`, and emits `change` only if changed _and_ `emit`. It deliberately does **not** reveal (a range end in a later month must not scroll the view back); callers that need it call `reveal` first.
- **Registries (module-level singletons, shared across entry points thanks to tsup code-splitting):** `modes.ts` (`registerMode/getMode`), `time.ts` (`registerTimeUI/getTimeUI`), `localization.ts` (`registerLocale`). Optional modules register themselves at import time → hence `sideEffects` and ESM-only.
- **Lifecycle:** constructor → `resolve(options)` (throws if mode/time module missing) → initial selection → `bindInput` → inline `mount()`. Popup DOM is built lazily on first `present()`; `setOptions` throws away and rebuilds the calendar (it bakes locale/classes/month count), keeping focus if it was inside. `destroy()` removes listeners, DOM, and only the attributes it added (`added[]`, plus `aria-controls`, `aria-invalid`), restores `readOnly`.
- **Popup:** appended to `appendTo ?? document.body`, `position: fixed` (class `tp-pop`), positioned by `place(anchor, pop, position, rtl)` on open/scroll(capture)/resize. `'auto'` flips above when there is no room below and more above; always clamped 8 px inside the viewport. While open: capture-phase `pointerdown` and `focusin` listeners close it when `composedPath()` contains neither the popup nor `anchor` (works through the web component's open shadow root). Focus returns to `opener` (the active element at open, ignoring `<body>`) or `el` — only if focus was inside the popup and `restoreFocus` is true.
- **Opening rules:** click on the input opens **without** moving focus when `allowInput` (so the user can keep typing); `ArrowDown`, `open()` and the WC toggle button move focus into the grid. `allowInput:false` ⇒ readonly and focus goes to the grid.
- **Input binding (`bindInput`)**: sets `aria-haspopup=dialog`, `aria-expanded`, `autocomplete=off` (only if absent); `click`, `input` (clears `aria-invalid`), `blur` (`commitInput(true)`), `keydown` (ArrowDown open/focus grid; Enter commit + close, prevents form submit if invalid or if the popup was open; Escape closes and stops propagation).
- **`commitInput(revertIfInvalid)`**: if text equals current `text()` → no-op. Empty ⇒ clear. Else `read(text)`; reject if `null`, more dates than `mode.max`, or any date `isDisabled`. Invalid: blur ⇒ revert text; Enter ⇒ `aria-invalid="true"` and keep text. Valid: `mode.clean` → `reveal(first)` → `setSel(…, true)`.

### Calendar (`Calendar.ts`)

- Root: `div.tp-dp(.tp-pop)` with `role=dialog aria-modal=true aria-label` (inline: `role=group`, no modal), `dir` from the locale, optional `data-theme`. Children: `.tp-months` (`position: relative`; 1–2 panels: nav buttons / `h2` whose month and year are `button.tp-title-btn`s + a hidden `.tp-sr[aria-live=polite]` with the plain title / `table[role=grid]` with `th[scope=col][abbr]`; while a value grid (month, year or time) is open `core/grid.ts` appends its overlay `.tp-time-panel` here and marks the month panels `inert`, §7.4, §7.9), optional time selector, `.tp-foot` (Today, Clear), hidden live region `.tp-sr[aria-live=polite]`.
- `update()`: if the visible month changed (`layoutKey = dayKey(view)`) → `layout()` **rebuilds all `td`s** (6 rows × 7 per panel, via `replaceChildren`) so assistive tech announces the newly focused cell (the header buttons are *not* rebuilt: only their text / `aria-label` change, §7.9), and an open month / year grid closes (focus to its trigger only if focus was inside the grid); otherwise `paint()` only patches class / `aria-selected` / `aria-disabled` / `aria-current` / `tabindex` (only writes when changed). Out-of-month cells are rendered `aria-hidden` and empty unless `showOtherMonths`. All-hidden rows get `aria-hidden`.
- Cells carry `data-k` (day key) and `aria-label` (full localized date). **Event delegation** on the root: `click` (cell → `pick`; `[data-a]` → `reset()` (closes the value grid) then prev/next/today/clear), `pointerover` (hover), `pointerleave`, `keydown` (Escape → first `grid.close(true)` (an open value grid closes, focus to its trigger, stop), else `close`; Tab → `trapTab` over `button, [tabindex="0"]` minus anything inside `[inert]`; Enter/Space → `pick`; arrows/Home/End/PageUp/PageDown via `keyboard.nextFocus`, Shift+Page = year, Left/Right mirrored in RTL).
- Prev/next use `aria-disabled` (never `disabled`) so focus is not lost at the limits. `nav()` moves `focus` by the same number of months as `view`.
- `ViewState.keys` holds selected day keys; `selected` styling/`aria-selected` = in `keys` **or** (`span` and not a hover preview and inside the span) — so a committed range's interior gets `.tp-selected` (accent) as well, which visually overrides `.tp-in-range` (a pre-existing look, see §11).

## 7. Feature deep-dives

### 7.1 Modes (`modes.ts`, `modules/range.ts`, `modules/multiple.ts`)

`Mode = { max, join, iso, autoClose, clean(dates), pick(current, day) → {sel, complete}, span?(keys, hover) }`.

- `single`: max 1, `autoClose` true. `range`: max 2, `join ' – '`, `iso '/'`, two clicks (order-free, sorted by `byDay`); `complete:false` after the first click ⇒ `pending`; `span` highlights start..end or start..hover. `multiple`: max ∞, toggles days, `autoClose` false, `complete` always true.
- `join` = separator in the _display text_, `iso` = separator in `isoInput`/WC `value`. `getDate()` returns a single value iff `mode.max === 1`.
- Adding a mode = implement `Mode`, `registerMode(name, mode)` at module top level, add a package export + tsup entry + `sideEffects` entry, and (for the WC) a loader in `XDatepicker.MODES`.

### 7.2 Typed input, format and parse (`format.ts`, `Datepicker.read`)

- `read(text)` order: **(1)** `parseValueList` (ISO dates/date-times and 9–11-digit timestamps — always accepted, unambiguous), **(2)** `parseDates(text, fmt, loc, time?)` (the display format).
- Formatting tokens: `yyyy yy MMMM MMM MM M dd d EEEE EEE`, `'literal'`. Month names in `MMMM/MMM` use the _in-date_ form (genitive in Ukrainian: "5 березня"), parse accepts every form (in-date/standalone × long/short, plus custom `months`).
- Default format is derived per locale from `Intl.DateTimeFormat(...).formatToParts` with `numberingSystem: 'latn'` and `calendar: 'gregory'` → e.g. `dd.MM.yyyy` (uk), `MM/dd/yyyy` (en-US), `yyyy-MM-dd` (sv).
- `parseDates` builds a regex from the format: separators are lenient (`[^\p{L}\p{N}]*`; literals with letters become optional), weekday names optional (and require a trailing separator so "Mar" is not read as "Ma"+"r"), `yy` uses a +50-year pivot, eastern-Arabic/Persian digits are normalised (`latin()` in `format.ts`, also used by the value grid's type-ahead), **leftover alphanumerics ⇒ invalid**, impossible dates (31.02) ⇒ `null`. It scans the whole text with `matchAll`, so a range/multiple text yields several dates ("05.03.2025 – 10.03.2025").
- With `time` (an `enableTime` picker) `parseDates` first lifts `HH:mm[:ss]` occurrences (`TIME` regex) out of the text; the i-th time pairs with the i-th date; no times ⇒ every date gets the picker's current `tod`; a count mismatch ⇒ invalid; `h>23, m>59, s>59` ⇒ invalid. Without `time`, a time in the text is invalid (unchanged legacy behaviour).
- Text shown in the input is `formatDate(d, fmt, loc)` plus `' ' + formatTime(d)` (always `HH:mm:ss`, not configurable) with `enableTime`, joined with `mode.join`.

### 7.3 Unix timestamps

Input: always understood (`parseUnix`, the 9–11 digit rule keeps `20250315` a date). Output: `outputTimestamp` ⇒ `toUnix(...)`. Date-only pickers normalise to a midnight (local, or UTC with `valueInUtc`), so timestamp→timestamp is _not_ identity there; with `enableTime` it is exact (to the second). Milliseconds are dropped everywhere. 13-digit (ms) timestamps are **not** recognised. **Before 1970:** `outputTimestamp` yields negative seconds and a negative `number` through the API (`selected`, `setDate`, `minDate`...) is accepted (`fromUnix`), but `parseUnix` is digits-only (`^\d{9,11}$`) and `-` is also the range / list separator. Typed text used to read `-1000000000` as the *positive* `1000000000` (2001-09-09, silently); now `parseValueList` returns `null` when `NEGATIVE` (`/(?:^|[-–—/,;])\s*-\s*\d{9,11}/`) matches: a `-` before a timestamp is a **minus sign** when the nearest non-whitespace character before it is the start of the text or another separator (`- – — / , ;`), so `-b`, `a, -b`, `a ; -b`, `a - -b`, `a – -b`, `a/-b`, `a / -b`, `a--b` are invalid. After a digit the dash stays the range separator (`a-b`, `a - b`, `a -b`; ISO dates with dashes are unaffected: their dashes never sit before 9+ digits). `read()` then falls through to `parseDates` (which also rejects it) and the input is **rejected as invalid** (`aria-invalid` on Enter, revert on blur). Whitespace between the minus and the digits is allowed too (`- 1000000000` is invalid, not a positive read). A `-123456789` string given to `selected` / the WC `value` is ignored (`parseUnix`), and in the WC `value` *attribute*, which is split on `/ , ;` and parsed token by token, a negative token is dropped like any unparseable token (`"1741996800/-1742428800"` keeps one date); it never becomes a positive date. Negative timestamps are still not accepted as text, and `parseUnix` was not changed. Also, timestamps below 100000000 (before 1973-03-03) have fewer than 9 digits and are not timestamps as text.

### 7.4 Time selector (`enableTime`)

- **Split:** core owns the data model **and the value grid** (`core/grid.ts`, §7.9); `modules/time.ts` owns only the three fields and registers itself via `registerTimeUI(factory)`. `Calendar` builds one `Grid` and `o.time?.({loc, cls, id, grid, change})`, inserts `ui.el` between `.tp-months` and `.tp-foot`; `paint()` calls `ui.set(state.time)`. The `TimeUI` contract is `{ el, set(t) }` (it used to have `close`; closing now belongs to the grid, which the calendar resets from `Calendar.reset()` — called by `Datepicker.hide()` on every popup close and by any `[data-a]` click, i.e. Today / Clear — and from Escape). `TimeUI` / `registerTimeUI` are not public exports (`index.ts` exports only `type Time`; the `./time` entry only `withTime`), so the contract could change.
- **UI (tap-to-grid, no typing):** `div.tp-time[role=group]` holds three `<button type=button class=timeField aria-haspopup=listbox aria-expanded>` named "Hours, 13" etc. (`loc.strings`, uk translated) with the colons between. A field click calls `grid.open({trigger, title, cols, selected, options, pick})`, clicking another field switches (the grid just gets new content), clicking the open one closes it (`grid.trigger === btn`); Enter/Space are the native button click. There is no typing on the fields and no auto-advance. Hours 6 cols x 4 rows, minutes/seconds **5 x 12** (the column count lives only in `FIELDS` in the module: it goes to the grid as `cols`, which writes it to `--tp-cols` for the CSS and reads it for the arrow keys); multiples of 5 in minutes/seconds get `cls.timeFive` (bold; per-option `cls`), so they form the first column; each option's `text` is the padded value and its `find` the unpadded one (type-ahead matches both); options are exactly `var(--tp-cell)` squares (§7.8); the current value is `selected`. Everything about the panel (header with the back button, listbox, inert siblings, `scrollTop`, roving tabindex, keys) is the shared grid's, see §7.9.
- **Keys:** see §7.9 (all five grids behave the same: 2D arrows without wrapping, Home/End, PageUp/PageDown, type-ahead, Enter on keydown and Space on keyup). Escape and Tab are deliberately _not_ handled in the grid: they reach `Calendar.onKey` (Escape closes the grid wherever focus is in the popup, then the popup on the next press; Tab goes through `trapTab`: back button → option → time fields → Today/Clear, month nav and the header buttons skipped because inert).
- **Pick:** `time[i] = v`, re-render the field (its `aria-label` carries the new value), `grid.close(true)` (focus to the field), `change([...time])`. The field label is updated locally because `Datepicker.setTime` does not repaint when nothing is selected. `set(t)` re-marks the selected option (`grid.select`) if one of the time fields' grids is open.
- **Reset:** `Datepicker.hide()` → `Calendar.reset()` → `grid.close()`; Today / Clear too (they are date actions; the user should see the days). `setOptions` rebuilds the calendar, which also returns to the days.
- **Semantics:** one `tod` for the whole picker. Picking a day → `stamp(day)` (copy with `setHours(...tod)`). Editing the selector → `setTime(t)`: `tod = t`; if a range pick is `pending` its dates are re-stamped and the view refreshed (does not cancel the pick), else `setSel(sel.map(stamp), true)` (fires `change`). Typed text with per-date times keeps them until the selector is touched. A date typed without a time takes `tod`.
- `closeOnSelect` default becomes `false` with `enableTime` (otherwise the popup would close before the time can be set); an explicit `closeOnSelect: true` still closes.
- **DST:** a non-existent local time (02:30 on 2025-03-09 in New York) is moved by JS to 03:30; `tod` follows via `timeOf(next[0])` and the input shows the normalised time.
- **Limits** are day-based; min/max/disabled don't constrain the time of day. Enabling/disabling `enableTime` at runtime adds `00:00:00` / drops the time (`setOptions` re-normalises `sel`).

### 7.5 `valueInUtc` — the UTC backend switch

Purpose (the user's words): backends that only speak UTC force every app to write local↔UTC conversion code; the picker should do it inside. **Values are UTC, display/edit is local.**

- **Date-only:** day ↔ UTC midnight. `selected: Date.UTC(2025,2,15)` shows "15 March" in every timezone; a picked day is reported as `2025-03-15T00:00:00.000Z` (without the flag a Kyiv user gets `2025-03-14T22:00:00.000Z`, the classic off-by-one-day). Timestamp UTC-midnight round-trips exactly in every zone. A mid-day UTC timestamp maps to its **UTC day**.
- **With `enableTime`:** `Date`/timestamps are already instants (no change). ISO strings become UTC: out `2025-03-15T11:07:09Z`; in: zone-less ⇒ UTC, `Z`/offset honoured, `.fff` accepted (`toISOString()` round-trips). A bare date string with time+utc ⇒ UTC midnight instant. The time selector and the input text stay local.
- Applies to _values only_ (§5). Passing a local-midnight `new Date(2025,2,15)` with the flag is read as a UTC value (⇒ the 14th for users east of UTC) — documented in the README.
- `setOptions({valueInUtc})` keeps the displayed day/time and changes what is reported.
- The web component hands the raw `value` tokens (`split(/\s*[/,;]\s*/)`) to the picker so the picker converts them (the element itself must never pre-parse values).
- README has a verified table (Kyiv, UTC+2): date-only local `…14T22:00:00.000Z` / `1741989600`; date-only UTC `…15T00:00:00.000Z` / `1741996800`; 15 Mar 13:07:09 local → `1742036829`, UTC iso `2025-03-15T11:07:09Z`.

### 7.6 Localization (`localization.ts`)

`resolveLocale(input?: string | LocaleObject, firstDayOverride?)`:

- code = input tag or `navigator.language` or `'en'`; invalid tags fall back to `'en'` (probed with `new Intl.DateTimeFormat(code)`).
- `registerLocale(obj)` registry, looked up by lower-cased tag, then its language prefix (that is how `locale="uk"` finds `locales/uk`). A `LocaleObject` passed directly is used as is.
- UI strings: English defaults, overridden by the locale object; `today` is auto-localised with `Intl.RelativeTimeFormat(code,{numeric:'auto'}).format(0,'day')` (capitalised) unless overridden. Other strings stay English unless provided (known mixed-language edge).
- First weekday: `locale.firstDayOfWeek` → `Intl.Locale#getWeekInfo()/weekInfo` → region table `SUNDAY_REGIONS` fallback (Monday otherwise). Direction: `getTextInfo()/textInfo` → `RTL_LANGS` regex.
- `title(d)` ("March 2025"), `label(d)` (full a11y date), `dow(i, long?)` (0 = Sunday), `month(i, short?)`, `monthIndex(name)`, `num(n)` (locale digits for grid numbers, **no grouping**: years print as "2026"), `titleParts(d)` (the title split by `formatToParts` or, with custom `months`, `[month, ' ', year]`; `title` itself is unchanged), `monthName(i)` (standalone name for the month grid), lazy `format` getter. `LocaleStrings` gained the required `month` / `year` (a type change: code that builds a whole `LocaleStrings` by hand must add them; `LocaleObject` is `Partial`, so locale objects are fine). Custom `months/weekdays` arrays bypass `Intl` for those names.
- Always Gregorian (`calendar: 'gregory'`) so `th`/`ar-SA` don't switch calendars.

### 7.7 Web component (`wc/XDatepicker.ts`)

- Shadow root (open, `delegatesFocus`): `<style>core+themes+LOCAL</style><div.wrap part=wrap><input part=input><button.toggle part=toggle>`. CSS arrives as text via tsup's `.css` text loader (hence `css.d.ts`); `LOCAL` styles the host/input/toggle. The input is boxed (border, radius, colours) from the `--tp-*` variables, which `core.css` / `themes.css` now also declare on `:host` (`:host([theme=dark])`, `:host(:not([theme=light]))` for the media query), because the input is a sibling of the popup, not inside `.tp-dp`. Page CSS (e.g. the demo's `input[type=text]` rule) never reaches the shadow input; that is why the demo's imperative inputs look boxed but the WC needed its own styles. Known gap: `theme` set only through `el.options` (not the attribute) styles the popup but not the input; and a page-level `--tp-*` on the host reaches only the input, as `.tp-dp` redeclares the variables. The popup is appended **into the shadow root** (`appendTo: root`, `anchor: wrap`). The shadow-local bare `input{…}` rule used to hit the (then text) time fields; the fields are buttons now and `LOCAL` has no bare `button` rule (only `.toggle`), so nothing local reaches them. Keep it that way, or beat it with `.tp-dp` specificity.
- **Date properties (`value`, `min`, `max`):** the setters call `reflect(name, v)` → `dateAttr(v)` → `setAttribute` / `removeAttribute`, so the attribute stays the single source of truth and the existing `attributeChangedCallback` flow does the rest (works before connect too). `dateAttr`: `Date` → `toISOString()` (invalid `Date`, `null`, `''` → remove), arrays joined with `,` (`tokens()` splits it again; range/multiple decided by `mode`). This is lossless because the `Z` string parses back to the same instant: checked `toDate(date)` vs `toDate(date.toISOString())` for 6 instants × time/utc flags × 7 zones (UTC, New York, Tokyo, Auckland, Kiritimati +14, St. John's −2:30/−3:30, Kyiv; set via IANA names in-process, offsets printed to prove they applied), 0 mismatches. Not covered: years outside 0000–9999 (`toISOString()` emits `+010000-…`, which the ISO regex rejects ⇒ ignored). Why properties exist at all: Vue 3 (and others) set a property when `key in el`, else `setAttribute(key, String(value))` — a `Date` bound to `max` used to become `Sun Nov 08 2026 …`, unparseable ⇒ silently no limit. So when adding a new date attribute, add a matching property.
- `ATTRS` maps attribute → `[option, parser]` (`year-range` → `yearRange` through `years()`: `^\s*(\d+)\s*-\s*(\d+)\s*$`, no match ⇒ `undefined` ⇒ the default range; a reversed pair is rejected by the picker, not the parser); `opts()` = attributes merged with `extra` (the `options` setter). A missing attribute parses to `undefined` ⇒ default, and `setOptions({...prev, ...undefined})` deliberately resets it.
- **Async init:** `connectedCallback` → `ready = init()`: `await load(opts)` (dynamic `import()` of range/multiple/time as needed) then constructs the picker with `isoInput: this.iso` (a detached hidden `<input>` whose `.value` backs the `value` getter and the form value). A `gen` counter cancels init if the element was disconnected meanwhile. `disconnectedCallback` → `teardown()` (destroy). Re-attach re-inits.
- `attributeChangedCallback`: `placeholder/label/disabled` handled directly; others are ignored until a picker exists; `value` → `setValue` (`setDate(tokens)` then `syncForm`); `inline` → teardown + init; everything else → `apply()` (async: load modules then `picker.setOptions(opts())`; the _attribute change is therefore applied asynchronously_ — tests/demo wait ~50 ms).
- Form association: `static formAssociated`, `attachInternals?.()`, `setFormValue?.()` (double-optional: jsdom has `attachInternals` without `setFormValue`). Value = `iso.value`. `formResetCallback` resets to the _current_ `value` attribute.
- `Base` falls back to an empty class when `HTMLElement` is undefined (SSR import safety); `customElements.define` is guarded in `wc/index.ts`.

### 7.8 CSS and theming (`styles/`)

- Variables on `.tp-dp`: `--tp-bg --tp-fg --tp-muted --tp-border --tp-hover --tp-accent --tp-accent-fg --tp-range --tp-focus --tp-radius --tp-cell --tp-pad --tp-z --tp-shadow` (+ `--tp-font`). Dark via `.tp-dp[data-theme=dark]` and `@media (prefers-color-scheme: dark){.tp-dp:not([data-theme=light])}` (the variable block is duplicated on purpose). `forced-colors` handled for the selected day.
- `.tp-pop` = `position: fixed; z-index: var(--tp-z)`; `.tp-dp[hidden]{display:none}` is required because the class sets `display`.
- **Host-page leakage:** the popup lives in `<body>`, so a host's global `button{…}` (or, before the tap-to-grid change, `input[type=text]{width:100%…}`) can hit the time fields. Library rules for them are prefixed `.tp-dp`; the time row is a 5-column grid, `width:100%; max-width: calc(7*var(--tp-cell))`, centred (so with two months it stays one month wide). The open field gets `[aria-expanded="true"]{border-color:var(--tp-accent)}`. Keep any new internal form control equally defensive.
- **Value grid CSS** (the time, month and year grids; the class names stayed `tp-time-*`, new: `.tp-title-btn`, `.tp-wide`, see §7.9): `.tp-months{position:relative}`; `.tp-time-panel{position:absolute;inset:0}` is a flex column whose children (header and list) are `max-width: calc(7*var(--tp-cell))` and centred, so the back button sits next to the grid even with two months. Options are **exactly the day cell**: `.tp-time-opt` is added to the `.tp-dow,.tp-day` size rule and to the `.tp-day` look / `:hover` / `:focus-visible` rules (no duplicated values; they sit _before_ `.tp-selected`, so `.tp-selected:hover` still wins); the list is a CSS grid of `repeat(var(--tp-cols), max-content)` tracks (the option's own `var(--tp-cell)` size, no second cell value), `justify-content:center`, `position:relative` so `offsetTop` is list-relative. **Why 5 columns:** day-sized cells make 10 columns 10 cells wide, over the 7-cell popup width; 5 columns fit, and each row is one 5-minute block (00-04, 05-09, ...), 12 rows. That overflows the 7-row viewport (the panel is as tall as the months block, so the popup cannot grow), hence the scroll. **Scrollbar:** `.tp-time-list` has `overflow-y:auto; scrollbar-width:thin; scrollbar-color:var(--tp-border) transparent; scrollbar-gutter:stable; overscroll-behavior:contain`, plus a `.tp-dp .tp-time-list::-webkit-scrollbar` fallback (6px, transparent track, `--tp-border` rounded thumb; engines that support the standard properties ignore it). It sits at the inline-end edge, so RTL mirrors it for free; the stable gutter keeps hours (no overflow) and minutes (overflow) from shifting sideways; `contain` stops a swipe at the list's end from scrolling the page behind the popup. The option/panel rules are not `.tp-dp`-prefixed (divs, not form controls); the back button reuses `.tp-nav`.
- **Input icon (`.tp-icon`):** an inline-SVG `background-image` on the bound `<input>` (no wrapper element, so the user's markup is untouched). It uses background _longhands_ (the `background` shorthand would wipe the input's colour) and a doubled class `.tp-icon.tp-icon` so a page's `input[type=text]{background:…;padding:…}` cannot override it; `:dir(rtl)` mirrors the position. The class name is a constant in `Datepicker.ts`, not part of `ClassNames`. The stroke colour is fixed (`#7d8590`, readable on light and dark), as data URIs can't use CSS variables.
- `classes` option replaces entries of `CLASSES` (in `Calendar.ts`); if a user replaces `root` they lose the variables and must supply their own CSS. No `content-visibility` is used (considered, deliberately skipped).

### 7.9 Month / year grids and the shared value grid (`core/grid.ts`, `Calendar.ts`, `Datepicker.ts`)

**What it is.** In each month panel the title `h2` holds two buttons, the month and the year (`type=button`, `aria-haspopup=listbox`, `aria-expanded`, `aria-controls` only while the grid is in the DOM, no `data-a`: gotcha 18), named "Month, November" / "Year, 2026" (`strings.month` / `year`). They open a grid in place of the days. It is **navigation only**: it never touches `sel` / `pending`, never fires `change`. Always on, in core, no option.

**Header.** `Calendar.panel()` builds the title once from `loc.titleParts(probe date)` (`Intl.DateTimeFormat#formatToParts`: `month` / `year` parts become buttons, everything else is a plain text node, in the locale's order: `2026年11月`, `листопад 2026 р.`). `layout()` only rewrites those nodes' text and `aria-label`s (`text()` writes only on change), so the buttons are **stable nodes**: focus, `aria-expanded` and listeners survive month changes (gotcha 11 does not apply to them). The probe assumes the parts' shape is the same for every month / year; checked for ~50 locales x 12 months x years 1, 99, 100, 1000, 1582, 2026, 9999. The `h2` is **not** `aria-live` any more: a live region made of buttons would read "Month, November Year, 2026". A hidden `.tp-sr[aria-live=polite]` sibling in `.tp-head` carries the plain `loc.title(d)` ("November 2026"), exactly what was announced before, once; the day table's `aria-labelledby` points at it. `Locale.titleParts` normalises U+202F in literal parts to a plain space (V8's `formatToParts` keeps the narrow no-break space that `format()` already turns into a space, gotcha 22); `Locale.title` is unchanged.

**The shared grid.** `createGrid({loc, cls, id, months}) → Grid`, one per `Calendar`. `Grid = { el, trigger, open(config), select(i), close(focus?) → boolean }`; `GridConfig = { trigger, title, options: {text, find?, cls?, today?, off?}[], cols, wide?, selected, pick(i) }`. Because there is one panel, **only one grid can be open across time, month and year**: `open` resets the previous trigger's `aria-expanded` / `aria-controls` and replaces the content. It owns: the panel (back button `cls.nav` + `data-a=back`, unit `h2` without `aria-live`, spacer) attached to `.tp-months` only while open with the other children `inert`; the `div[role=listbox]` of `div[role=option]` (divs: gotcha 14) built from a prototype `cloneNode`; `--tp-cols`; the roving tabindex; `scrollTop` handling (centred on open, minimal adjustment, `focus({preventScroll:true})`, never `scrollIntoView`); per-option classes (`cls.timeOpt`, option `cls`, `cls.today` + `aria-current=date`, `cls.disabled` + `aria-disabled`, `cls.selected` + `aria-selected`); and the keys. The option elements are kept in a plain array (`els`): indexing the live `list.children` of 9999 years is O(n) in jsdom (opening took 5.5 s, 0.17 s with the array). Existing `ClassNames` keys were not renamed: the grid reuses `timePanel` / `timeList` / `timeOpt`; new keys are `titleBtn` (header buttons) and `wide` (modifier on the list).

**Keys (panel `keydown`/`keyup`; all handled keys stop here; Escape and Tab never do):** ← → ↑ ↓ in 2D, no wrap (← → continue across row ends, mirrored in RTL); Home / End; PageUp / PageDown move by the number of fully visible rows (`floor(clientHeight / optionHeight)`) in the same column, clamped (a list that does not overflow, i.e. hours and months, has one page: first / last row of the column); Enter picks on keydown; **Space** is `preventDefault`ed on keydown and picks on **keyup** (only if its keydown happened on an option: `spaceDown`), because after a pick focus lands on the trigger and a Space keyup there would click it and reopen the grid in engines that click buttons on keyup (gotcha 19); Ctrl / Meta / Alt combinations are ignored. **Type-ahead:** a printable key (not Space) appends to a buffer that resets after 500 ms (`e.timeStamp`, no timer); the buffer is lower-cased with `toLocaleLowerCase(loc.code)` and Arabic-Indic / Persian digits go through `latin()` (shared with `parseDates`). The **whole buffer is tried first** as a prefix of each option's `text` *or* `find` (so `5` and `05` both reach minute 5, `11` reaches hour 11, `1985` reaches 1985, «бе» reaches березень); only if nothing matches **and** the buffer is one repeated character does it cycle through that character's matches after the focused option (`jj` → January, June, July, wrapping). A miss keeps focus.

**Month grid.** 12 options, 3 columns, `wide`. Labels are the standalone (nominative) names: `Locale.monthName(i)` = custom `months[i]` else `Intl` `{month:'long'}` alone ("листопад", not the in-date genitive `month()` returns). Selected = the month of that panel; today marker on the real current month (compared to `s.today`); `off` (`aria-disabled`, focusable, not pickable) when the month lies **entirely** outside `minDate` / `maxDate` (`Datepicker.monthOff`, only min/max, not `disabledDates`).

**Year grid.** 4 columns, `wide`, scrolling list. Labels `loc.num(year)` (`find` = the latin `String(year)` so typed latin digits match even in `ar`); `loc.num` now uses `useGrouping:false` (it printed "2,026" / "2.026" / "2 026"; days are unaffected). `Datepicker.yearSpan()`: `yearRange` if two integers with `from <= to`, else this year ± 100 (so a reversed or invalid range falls back to the default); `lo` / `hi` **years replace** the ends (the resolved picker dates, not the raw options); if that leaves `from > to` the limit that replaced an end wins (`yearRange [2000,2010] + minDate 2020` → just 2020); clamped to **1..9999** (year 0 prints as "1" in `Intl`, years above 9999 break ISO: `toISOString` gives `+010000-…`); then widened to the years on show (view and, with two months, panel 2), after the clamp, so the selected option always exists. Because `minDate` / `maxDate` are the ends, no year option is ever disabled (only the widening can add years beyond them, and only when the view got there). Up to 9999 options are created when the grid opens; measured only in jsdom (§9).

**Pick.** `Calendar.toggleGrid` builds the config; `pick(k)` calls `on.show(month, panel)` **first** and then `grid.close(true)`, so the trigger already carries the new value when focus lands on it. `Datepicker.show`: focus day = the current focus's day of the month clamped to the target month's length (31 Jan → 28 Feb), then `reveal(date, panel)` which clamps to min/max (a year pick that lands outside min/max therefore ends in the nearest allowed month) and puts the month in `panel` (picking from panel 2 sets `view` to the chosen month − 1; if that is before `monthStart(min)`, `reveal`'s existing rule moves it). `monthChange` / `yearChange` fire through `setView`. A month change makes `update()` → `layout()` close the grid (it no longer matches the view); focus moves to the trigger **only if it was inside the grid**, so the same path serves picks (focus was in the grid) and API navigation (`jumpToDate`, `setDate`, `setRange` while a month / year grid is open: focus outside the popup is never stolen). A pick that doesn't change the view leaves the grid open until `grid.close(true)` right after `show`. The time grid is not closed by a view change.

**Closing.** `Calendar.reset()` (popup close, Today / Clear, any `[data-a]` click), Escape (first press, focus to the trigger), the back button, a second click on the open trigger, `setOptions` (the calendar is rebuilt) all close whichever grid is open. `close(true)` first removes `inert` from the months block's children, then focuses the trigger, then detaches the panel: browsers refuse to focus an inert element (the month / year triggers sit inside the inert panels; the time fields don't, which is why the time grid never hit this; jsdom doesn't implement `inert`, so tests can't catch it: gotcha 20).

**CSS.** `.tp-dp .tp-title-btn` (prefixed, like the time fields; transparent 1px border so the size doesn't change; hover background; `[aria-expanded="true"]` accent border; no chevron). `.tp-wide` on the list: `grid-template-columns:repeat(var(--tp-cols),minmax(0,1fr))` and `.tp-wide>.tp-time-opt{width:auto}`: the columns share the list's full width (one month wide, scrollbar gutter included) instead of `7·cell/n`, which for 4 year columns would overflow by the gutter. Time options stay `var(--tp-cell)` squares.

## 8. Traps and gotchas learned the hard way

1. **`.map(formatISO)` / `.map(toDate)` pass the array index as the 2nd argument** — which is now the `time` flag (`formatISO(d, time, utc)`, `toDate(v, time, utc)`). Always use a lambda. (`list.map(toDate)` was a real bug I avoided; tests broke on `.map(formatISO)`.)
2. **Double conversion** of already-converted dates (§5 "must NOT").
3. **CRLF:** Python on Windows rewrites `\n` → `\r\n` when you `open(p,'w')` text files. Use `open(p,'rb')…write(bytes)` and assert `'\r\n' not in text`, or the Edit tool. After scripted edits run `grep -rlU $'\r' src demo README.md package.json` (must print nothing) and `git diff --stat` (a whole-file diff = line-ending damage; fix with `sed -i 's/\r$//'`).
4. **Unquoted bash heredocs expand `$(...)`/backticks** — never put JS selectors like `$('#a')` in `<<EOF`; use a quoted `<<'EOF'` or the Write tool. Git-Bash `/tmp` is not visible to Windows Python (`cygpath -w`).
5. **Windows Node ignores IANA names in the `TZ` env var at startup** (`TZ=America/New_York` silently stays in the machine zone; `TZ=UTC` and POSIX strings like `EST5EDT` do work). Assign `process.env.TZ` inside the process (preload, §9). I once reported multi-timezone passes that were not real.
6. **jsdom limits:** `matches(':focus-within')`/`:focus` crash inside shadow roots (dom-selector bug); no layout (`getBoundingClientRect` zeros); `ElementInternals.setFormValue` missing; Node's global `Event`/`EventTarget`/`CustomEvent` must be replaced by jsdom's or `dispatchEvent` throws.
7. **`outerHTML` does not serialise `.value` properties** — copy values to attributes before snapshotting markup for screenshots.
8. **tsx cannot import `.css`** (the WC does): copy `src` to a scratch dir and replace the two `import … from '…css'` lines with `const core = ''`.
9. **Demo file is Prettier-formatted by the user**: read the current text before editing; regex/replace with exact strings and `assert count == 1`.
10. **Web component attribute changes are async** (`apply()` awaits module loading): in the demo/tests wait ~50 ms before reading derived state.
11. `Calendar.layout()` creates new `td`s on month change — a held reference to a cell is stale after navigation. Focus is re-applied via `focusTd` in `paint()`.
12. `setSel` does not `reveal`; if you add a caller that changes the selection from outside the visible month, reveal first.
13. IDE diagnostics (`unused import`, `Cannot find name`) appear transiently _between_ multi-step edits; judge only the final `tsc --noEmit`.
14. **Time grid options must not be `<button>`s**: `trapTab` collects every `button` plus `[tabindex="0"]`; 60 buttons would break first/last detection. Anything in `.tp-months` that must be skipped while a grid is open has to be inside an `[inert]` element (`trapTab` filters on `closest('[inert]')`; jsdom does not implement `inert`, it is only an attribute there, so jsdom focus still lands on inert cells; real browsers refuse).
15. **A grid pick moves focus off an element that is about to be removed**: `Grid.close(true)` focuses the trigger _before_ the panel is detached, so focus never falls back to `<body>` in between (but after removing `inert`, gotcha 20).
16. **`Datepicker.hide()` must call `cal.reset()` after it has read `matches(':focus-within')`** (the grid may hold the focus) and the reset must not move focus (the popup is being hidden; focus restore is `hide`'s job). Today / Clear call `reset()` without focus too.
17. **Grid keys vs `Calendar.onKey`**: it ignores keys whose target is not a `td[data-k]`, but arrows/Enter/Space/Home/End/PageUp/PageDown and type-ahead characters are still stopped in the panel so nothing else (host handlers on ancestors) sees them. If you add a handled key to the panel, stop it there; do **not** stop Escape or Tab.
18. `Calendar`'s `[data-a]` click branch now calls `reset()` for _any_ `data-a` (including the grid's own back button, which has already closed itself with focus). Do not give a non-closing control a `data-a` (the month / year buttons have none and are wired with their own listeners).
19. **Space picks on keyup, in every grid.** If Space picked on keydown, focus would move to the trigger and the Space _keyup_ would land on that button, which Firefox / Safari may treat as a click and reopen the grid (Chromium only clicks on keyup if the keydown happened on the button). So keydown is `preventDefault`ed and only arms `spaceDown`; the keyup on an option picks. Enter stays on keydown. Not verified in Firefox / Safari (§9). A repeating Enter (held key) still reaches the trigger after the first pick and clicks it: pre-existing, untouched.
20. **Un-inert before focusing a trigger inside the months block.** `.tp-months`'s children are `inert` while a grid is open and the month / year buttons live in them: a real browser silently refuses `focus()` on an inert element. `Grid.close` removes `inert` first, then focuses, then detaches. jsdom ignores `inert`, so tests cannot catch a regression here; the time fields sit outside `.tp-months`, which is why the old code never needed this.
21. **The header's buttons are stable nodes; the live text is separate.** `layout()` only rewrites their text / `aria-label` (never `replaceChildren` the title), and the month announcement comes from the hidden `.tp-sr[aria-live]` span, not the `h2` (an `aria-live` heading made of buttons reads "Month, November Year, 2026"). If you change the title structure, keep both properties, and keep `aria-labelledby` of the day table on the span.
22. **`formatToParts` is not `format()`**: V8 keeps U+202F (narrow no-break space) in literal parts ("2026 г." / "р.") where `format()` yields a plain space, so joining the parts differs from `title(d)` by an invisible character. `titleParts` normalises it; `title` stays the `format()` result.
23. **`loc.num` must not group** (`Intl.NumberFormat('en').format(2026)` is "2,026", `de` "2.026", `uk` "2 026"): it is used for year labels. `useGrouping:false` changes nothing for days 1-31.
24. **Do not index `list.children` of a 9999-option grid**: a live `HTMLCollection` is O(n) per access in jsdom (opening took 5.5 s). `grid.ts` keeps the option elements in an array.
25. **Type-ahead order matters**: whole buffer as a prefix first (`11` → hour 11), repeated-character cycling only as a fallback (`сс` → the next «с…» month). The other way round makes hour 11 unreachable by typing. Options match their visible text *and* `find` (the unpadded value), so `05` and `5` both work.
26. **`Date` for year < 100**: never `new Date(y, m, d)` (it maps to 19xx); `makeDate` uses `setFullYear`. In zones west of UTC the instant `0001-01-01T00:00:00Z` is local 31 Dec of year **0**: the picker shows it as year 0 ("1 BC" in `Intl`), reachable only through such values or the arrows (§11).
27. **Windows + Edge screenshots**: pass `--screenshot=C:/…/x.png` with forward slashes (a `\\` path built in a shell function wrote one literal `shots$1.png`); `--hide-scrollbars` also hides the thin list scrollbar you are trying to check.

## 11. Known limitations and open items

- **Core is ~8.9 KB gz (at `b5396cc`) vs the 7.5 KB goal, and the month / year grids made it bigger** (`grid.ts` ~ 150 lines, header, `yearSpan`, `titleParts`...): **re-measure after the next build** (§10 command). Candidates to trim: caching/removing `Intl` helpers, simplifying `parseDates`, dropping rarely-needed paths, moving timestamp/UTC parsing behind a module. The grids are in core by requirement, not a module.
- No tests in the repo; no CI.
- Spec items not done: presets module, a built-in "inline" module split (inline lives in core), CJS.
- **Month / year grids:** the year list is built when the grid opens (up to 9999 divs; no virtualisation; real-browser cost unmeasured). Day navigation (prev / next, arrows, `PageUp`) is **not** limited to years 1-9999: it can reach year 0 ("1 BC" in `Intl`) and year 10000, and the year grid then widens past 9999 to include the shown year. The 1-9999 limit applies to the year *list*. In zones west of UTC a UTC instant at the very start of year 1 is local year 0 (gotcha 26). Month availability looks only at `minDate` / `maxDate`, not at `disabledDates` / `disabledDaysOfWeek`. No `aria-posinset` / `aria-setsize` on the options. Typed negative timestamps are rejected as invalid (§7.3). In the WC `value` attribute a negative token is dropped (not rejected as a whole), as any unparseable token is.
- `DatepickerOptions.outputTimestamp` JSDoc still says "local midnight" and does not mention `valueInUtc`; `DateInput` JSDoc mentions only `yyyy-MM-dd` although date-times/zones are accepted; `jumpToDate(date: Date)` is typed `Date` but accepts any `DateInput` at runtime. (Doc debt, harmless.)
- Time selector: `HH:mm:ss` only; one shared time in range/multiple; day-based min/max; new picks default to `00:00:00` (not "now"); "Today" picks the **local** today even with `valueInUtc`.
- Range interior cells use `.tp-selected` (accent) rather than the lighter `.tp-in-range`; may deserve a design pass.
- `parseDates` rebuilds its regex on every call (no caching); fine for typed input.
- UI strings other than `today` default to English for every locale except `uk` (mixed-language UI for e.g. `fr` unless the user passes strings).
- WC: `value` setter writes the attribute, so form reset returns to the last assigned value, not the original; `attributeChangedCallback` for most options is asynchronous.
- The WC `name` attribute is only used by form association (needs `ElementInternals`, Safari 16.4+); older browsers do not submit it.
- Millisecond timestamps (13 digits) are rejected as invalid text.
- Accessibility is implemented to the WAI-ARIA pattern but **never tested with a screen reader**.
- SSR: modules import safely (guards for `HTMLElement`), but constructing a `Datepicker` needs a DOM.

## 12. Decision log

- **ESM-only, single package with subpath exports** instead of a monorepo — simplest publishing; modules tree-shake by import.
- **Optional features self-register** (modes, time UI, locales) so core pays nothing for them; the cost is import-time side effects (`sideEffects` whitelist).
- **Calendar rebuilds day cells on month change** (not in-place updates) for screen-reader announcement; selection/hover only patches attributes.
- **Open on click without stealing focus** when typing is allowed; keyboard open moves focus in.
- **Date format is token based, not `Intl` options** (parse needs a deterministic pattern); default pattern is derived from `Intl` so it stays locale-correct.
- **Timestamps are seconds, 9–11 digits** so `yyyyMMdd` can never be mistaken for one; ms not supported.
- **`outputTimestamp` changes the returned _type_** (explicitly requested by the user); `DatepickerValue` was widened rather than making the class generic.
- **Time selector is a module + registry**, `closeOnSelect` defaults off with time, one shared `tod`.
- **`valueInUtc` converts at one boundary (`Day.ts`)** and means "values are UTC" (not "display UTC"). Name chosen to be self-explanatory; alternatives considered: `utc`, `convertUtcToLocal`.
- **HH:mm:ss display is fixed** (user said "by default"; no `timeFormat` option was requested).
- **`.tp-dp`-prefixed selectors for form controls** inside the popup to survive aggressive host CSS.
- **Time fields are tap-to-grid buttons, not text inputs** (replaces the spinbutton design): no typing on the fields (typing stays on the main input via `parseDates`), no auto-advance hours → minutes → seconds, no steps. The grid is an overlay inside `.tp-months` so the popup never changes size; Today / Clear close it (date actions); Escape is layered (grid first, then popup); an open field is marked with an accent border; `aria-controls` is set only while the grid is in the DOM. Cost in core: four class names, `TimeUI.close`, `TimeUIOptions.months`, `Calendar.reset`, the `trapTab` filter, `h` exported for the module.
- **Time grid options are day-cell sized, minutes/seconds are 5 x 12 with a thin visible scrollbar** (replaces the first 10 x 6 grid with a hidden scrollbar): tiny options were hard to hit, and day-sized cells cannot be 10 across in a 7-cell width. The grid still keeps the popup's size, so the overflow scrolls; the scrollbar is visible (a hidden one hides that there is more) but thin, in `--tp-border`, so it works in both themes.
- **Month / year grids are core, always on, no option** (user requirement), and they **share one value grid with the time selector** (`core/grid.ts`) instead of a second overlay: that makes "one grid at a time" structural and removes the duplicated panel / keys / scroll code. Consequences: `TimeUI` lost `close` and `TimeUIOptions.months` for `grid`; `h` / `cx` / `attr` moved to `core/dom.ts` (no import cycle); existing `ClassNames` keys kept (the grid reuses `timePanel` / `timeList` / `timeOpt`), `titleBtn` and `wide` added; `LocaleStrings` gained required `month` / `year`.
- **Header buttons are stable nodes and the live announcement moved to a hidden span** (see gotcha 21): keeps the old "November 2026" announcement exactly, avoids double announcements, and lets focus / ARIA state survive `layout()`.
- **Year list ends come from `lo` / `hi`, widened to the shown years, clamped to 1-9999 before the widening** so the selected option always exists; a reversed / invalid `yearRange` falls back to the default; if `minDate` / `maxDate` reverse the range, the limit that replaced an end wins.
- **Wide grids use `1fr` tracks, not `7·cell/n` options** (the stable scrollbar gutter would overflow four `7·cell/4` columns); time options stay exact day-cell squares.
- **Pick = `show()` then `close(true)`; a month change closes a month / year grid (focus moved only if it was inside)**: the trigger's label already has the new value when focus lands on it, and API navigation never steals focus.
- **Type-ahead: whole buffer first, repeated-character cycling only as a fallback; options match their text and their unpadded value** (user-confirmed refinement of the first spec, which made hour 11 unreachable).
- **Space picks on keyup in all grids** (user decision, gotcha 19); Enter on keydown.
- **`parseUnix` left alone; a typed negative timestamp is invalid** (user instruction, follow-up): `-` is the range separator, so instead of accepting negatives, `parseValueList` rejects a timestamp preceded by a minus whose previous non-space character is the text start or another separator (`- – — / , ;`; a one-line `NEGATIVE` guard), rather than silently reading it as the positive timestamp. A dash after a digit stays the range separator. Whitespace after the minus is also covered (a deliberate widening of "directly followed", so `- 1000000000` can't read as positive).
